## Processed dataset v1 (the contract between units)

Built by unit 02 (`units/02-shape-and-metrics/build_dataset.ipynb`): locally from the small subset
(the 27 usable subjects), and on Kaggle from the full 1,228 (streamed subject by subject out of the remote zip,
screened with the students' `touches_scan_edge` + the metal rule of `data/scripts/screen_local.py`).

Location: `env.processed_root() / "v1"` (Kaggle: the attached dataset `pelvis-xray3d-v1`; Colab: unzipped
from Drive by `dataset.ensure_local()`). Never in git.

- `index.json`: `{"version": 1, "subjects": [...], "geometry": {...}, "created": ..., "source": ...}`.
- `<sid>.npz` per subject:
  - `occ`: `(64, 64, 64)` uint8, pelvis occupancy (hip_left ∪ hip_right ∪ sacrum).
  - `ap`, `lat`: `(128, 128)` float32, line integral `p` of the **whole** CT (DiffDRR, perspective).
  - `ap_bone`, `lat_bone`: same rendering of the pelvis voxels only (oracle silhouettes, unit 03).
  - `center_mm`: `(3,)` the cube centre in the CT's world coordinates (mm).
  - `femoral_heads`: `(2, 4)` `[x, y, z, r]` mm in the cube frame, rows (left, right), NaN if missing (for `ce_angle`).
- `screening.json`: why each screened subject was kept or rejected. A pelvis whose occupancy touches a face of the
  cube is rejected (too big for 320 mm).

**The canonical cube:** 64³ voxels over a fixed **320 mm** cube (5 mm voxels), centred on the centre of the
pelvis mask's bounding box, array axes in **RAS** order (index i → patient's Right, j → Anterior,
k → Superior). The size is fixed (not scaled per patient) so the network sees real scale. Resampling: linear
for CT, the mask resampled as float then thresholded at 0.5. Voxel i's centre is at (i + 0.5)·5 − 160 mm; the
patient's Left is −x.

**Image orientation** (same as unit 01's `ap_lat_views`): rows run head → feet; AP columns run patient's
Right → Left; LAT columns run Anterior → Posterior.

**Geometry** (stored in `index.json`, used everywhere): source–detector 1,020 mm, source–isocentre 750 mm
(close to DeepFluoro's ≈744 mm, so magnification ≈1.36 in both), detector 128 × 128 pixels of **4.0 mm**
(≈376 mm field at the isocentre; 3.0 mm was the first plan, but the widest pelvises overflowed the AP image
once magnified 1.4–1.5× at the front). Always read the values from `dataset.geometry()`, never hard-code them. The isocentre is the cube centre. The CT given
to DiffDRR is a 480 × 480 × 400 mm box around the cube centre, padded with air outside the scan.
`dataset.camera(view)` returns `K, R, t` in the cube's frame (mm, origin at the cube centre, RAS axes) such that
`xray3d.geometry.project_pinhole` maps a point to its pixel in that view's image. **Acceptance test:**
projecting the GT occupancy voxels must reproduce the `*_bone` silhouette (IoU ≥ 0.9 for both views).

## Network contract (units 04–08)

- Input `(B, V, 128, 128)` float32, V = 1 (AP) or 2 (AP, LAT), each image standardised per image
  (zero mean, unit std) by `torchdata` (the same function is applied to real X-rays in unit 07).
- Output logits `(B, 1, 64, 64, 64)` in the canonical cube (RAS axes). Occupancy = sigmoid > 0.5.
- `XrayTo3D(n_views)`: a 2D encoder per view (128² → 16² feature maps; first planned as 8²), **lifting along each view's ray axis**
  (AP features broadcast along A, LAT along R, matching the image orientation above), fusion by sum or concat,
  a 3D decoder 16³ → 64³ (transposed convs; first planned as 8³). Students write the layers and the lifting.
- **As built (unit 04), following video 10 rather than the first plan's 8² → 8³:** a 16² bottleneck with lifted skip
  connections at 32³ and 64³ (video 10 shows that a 16³ round trip without skips tops out around Dice 0.67), about a
  quarter of the video's channels; InstanceNorm (BatchNorm's eval statistics were unstable at batch 2–8); fusion
  `"concat"` by default; a `dropout` argument (`Dropout3d` at the coarsest fused volume) for unit 07's MC dropout.
  `XrayTo3D(n_views=2, fuse="concat", dropout=0.1)`: 365 k parameters with 1 view, 679 k with 2.
- Loss: BCE + soft Dice (proposal). Training: Adam, batch 8, 3,000–5,000 iterations (proposal), on Colab/Kaggle GPU.
  Locally: the overfit-one-batch test and a few iterations on CPU only.
- Checkpoints: `{"model": state_dict, "config": {...}, "step": n, "seed": s}`, saved under
  `env.processed_root() / "runs" / <run name>`; on Colab also copied to Drive. On Kaggle runs go to `/kaggle/working/runs` (the
  processed root is the read-only input dataset there); override with `XRAY3D_RUNS`. Checkpoints also hold
  `optimizer` and `best_val_dice` for resuming. The validation metric is `training.validation_dice`.

## Unit content (TODOs are the students'; everything else Claude's)

- **02 · shape and metrics** (videos 05, 06). Part A: the cube: `cube_grid` (voxel centres in mm), resampling
  through the inverse affine (`map_coordinates` is the plumbing; choosing interpolation order and threshold is the
  concept), occupancy, marching cubes (skimage) → a mesh in mm. Part B: metrics: `dice`, `iou`, `surface_voxels`,
  `surface_distances` (via a distance transform), `hd95`, `assd`, `nsd` (1.5 mm and 5 mm, see the note below),
  `chamfer`, and one clinical angle (a simplified centre-edge angle, as in the class deck); sanity tests
  (GT vs GT perfect, empty vs GT worst). Part C: `build_dataset.ipynb` (Claude) + the Kaggle full build.
  *NSD note:* with 5 mm voxels a 1.5 mm tolerance is below one voxel; report both 1.5 mm (the proposal's) and 5 mm
  and explain it in the explainer.
- **03 · baselines** (videos 07, 08). Visual hull from the oracle silhouettes, carved by projecting voxel
  centres with `project_pinhole` and `dataset.camera`; nearest neighbour retrieval (L2 on downsampled,
  standardised DRRs, train → test); both scored with unit 02's metrics on the test split; results table to
  `results/baselines.csv`.
- **04 · the network** (videos 09, 10). `conv2d_naive` vs `nn.Conv2d`, `conv_out_size`, `ConvBlock`,
  `Encoder2D`, `lift_view`, `Decoder3D`, `XrayTo3D`; shape checks with dummy batches; parameter counts.
- **05 · training** (videos 10 end, 11). `soft_dice_loss`, `bce_dice_loss`, `train_step`; overfit one batch;
  the first real run on Colab/Kaggle; reading the curves.
- **06 · the controlled experiment** (video 12). Arm 1: 1 view vs 2 views, 3 seeds each, everything else fixed.
  Arm 2 (the proposal's second comparison, Claude's choice of its two options): training-set size, 25 % vs 100 %
  of train, 2 views (the LAT-tilt option needs re-rendering; size doesn't). Students write the summary statistics
  and the paired comparison; Claude writes the run script. Results to `results/experiment_v1.csv`.
- **07 · simulated vs real** (video 13). DeepFluoro's real frames are all near-AP (largest angle between any two
  frames of a specimen: 11–49°), so there is **no real lateral view**. The gap is measured two ways: the 1-view
  model on a real frame vs on a DRR rendered at the same pose with DiffDRR; and the 2-view model on (real AP +
  simulated LAT) vs (simulated AP + simulated LAT). GT = DeepFluoro's pelvis labels mapped into the canonical cube
  with the students' unit 02 functions. Plus the error analysis (Dice vs the clinical angle, the worst cases),
  the re-projection check, and MC-dropout uncertainty. **Nothing derived from DeepFluoro is committed** except
  aggregate numbers in `results/`.
- **08 · putting it together** (video 14). `predict_from_xrays` end to end (two images → mesh), the demo,
  the report outline (with the licence section and the personal-contribution table built from the units' logs).
